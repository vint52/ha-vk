# Дизайн: поддержка команд в сообщениях VK (issue #10)

Дата: 2026-08-31
Ишью: https://github.com/vint52/ha-vk/issues/10

## Задача

Дать пользователю возможность обрабатывать команды с параметрами из входящих
сообщений VK, например `/light kitchen off`, без ручного парсинга текста в
шаблонах автоматизаций.

## Решение (общая идея)

Интеграция сама распознаёт команды и кидает отдельное событие Home Assistant
`ha_vk_command` с уже разобранными полями `command` и `args`. Выполнение
команд остаётся на стороне автоматизаций пользователя — интеграция ничего не
включает и не выключает сама. Новых опций конфигурации нет.

## Распознавание команды

- Команда — сообщение, чей текст начинается с `/` и содержит хотя бы один
  непробельный символ сразу после `/`. Строки `/`, `/ foo`, пустой текст —
  не команды.
- Ведущие/замыкающие пробелы текста игнорируются.
- Первое слово без `/` — имя команды; приводится к нижнему регистру, чтобы
  `/Light` и `/light` совпадали в триггерах автоматизаций.
- Остальные слова (разделитель — любые пробелы) — аргументы.

Реализация: чистая функция `parse_command(text: str) -> dict | None` в
`custom_components/ha_vk/receiver.py`. Возвращает `None`, если текст не
является командой, иначе `{"command": ..., "args": [...], "args_text": ...}`.

## Событие `ha_vk_command`

Кидается ресивером (`VkIncomingMessageReceiver._process_updates`) сразу после
обычного события `ha_vk_incoming_message` для того же сообщения. Событие
`ha_vk_incoming_message` кидается всегда, как раньше, — обратная
совместимость с существующими автоматизациями сохраняется.

Payload — все поля нормализованного входящего события (`entry_id`,
`group_id`, `peer_id`, `from_id`, `conversation_message_id`, `message_id`,
`event_id`, `date`, `text`, `attachments`, `raw_event`) плюс:

- `command` — имя команды в нижнем регистре, например `"light"`;
- `args` — список аргументов, например `["kitchen", "off"]`;
- `args_text` — хвост строки после имени команды как есть (обрезанный по
  краям), удобно для команд со свободным текстом (`/say Привет мир`).

Пример: текст `/light kitchen off` даёт `command="light"`,
`args=["kitchen", "off"]`, `args_text="kitchen off"`.

## Константы

В `const.py`: `COMMAND_EVENT = "ha_vk_command"`.

## Обработка ошибок и безопасность

- Фильтрация по настроенному `peer_id` и отбрасывание исходящих сообщений уже
  выполняются в `normalize_incoming_message_event` и автоматически
  распространяются на команды.
- Не-командные сообщения просто не порождают второе событие; ошибок это не
  вызывает.

## Тестирование

- Юнит-тесты `parse_command`: обычная команда с аргументами, команда без
  аргументов, регистр, лишние пробелы, пустой текст, `/`, `/ foo`,
  сообщение без префикса.
- Тесты ресивера (`tests/test_receiver.py`): командное сообщение кидает оба
  события с корректным payload; обычное сообщение кидает только
  `ha_vk_incoming_message`.
