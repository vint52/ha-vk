# Changelog

Все заметные изменения в проекте `ha-vk` будут собираться в этом файле.

## Unreleased

### Добавлено

- Reauth-флоу: при протухании токена Home Assistant предложит ввести новые токены без удаления интеграции. Receiver сам запускает reauth при ошибках авторизации VK.
- Типизированные исключения API-клиента (`VkAuthError`, `VkNetworkError`, `VkLongPollError`) с кодами ошибок VK — классификация ошибок больше не зависит от текста сообщений.
- Тесты notify-сущности, wall-поста с фото и фолбэка видео→документ.
- Повторы отправки при сетевых ошибках с экспоненциальным backoff (1с → 2с → 4с…, максимум 60с): ретраятся вызовы VK API, скачивание медиа и загрузка на upload-серверы; `messages.send` и `wall.post` защищены от дублей (`random_id`/`guid`). Количество повторов настраивается в параметрах интеграции (по умолчанию 3, 0 — отключено). (#11)

### Изменено

- Runtime записи хранится в `entry.runtime_data` вместо `hass.data` (требуется Home Assistant 2025.3+, указано в `hacs.json`).
- Receiver работает как background task записи, переживает любые неожиданные исключения и переподключается с экспоненциальным backoff (5с → 5мин).
- Версия VK API по умолчанию поднята с 5.131 до 5.199.
- В `strings.json` и переводах добавлена секция `config.abort` — сообщения `already_configured` и `reauth_successful` теперь показываются текстом, а не сырым ключом.

### Исправлено

- Утечка aiohttp-сессий при валидации в config flow: используется общая сессия Home Assistant вместо создания новой на каждую попытку.
- `messages.send` теперь передаёт случайный `random_id`, чтобы VK дедуплицировал повторные отправки при сетевых таймаутах.

## 1.0.1 - 2026-04-15

### Исправлено

- В `Параметры` интеграции снова доступны `VK access token` и `VK peer ID`, а изменения теперь корректно сохраняют `config entry data` и обновляют `unique_id`.
- Добавлена защита от конфликта записей `ha-vk` при совпадении пары `peer_id + group_id` после редактирования.

## 1.0.0 - 2026-04-15

### Добавлено

- Поддержка входящих сообщений сообщества VK как событий Home Assistant `ha_vk_incoming_message`.
- Фоновый long poll receiver с автоматическим переподключением и корректной остановкой при выгрузке записи интеграции.
- Отдельные примеры автоматизаций и сценариев использования в `docs/examples.md` и `docs/examples.en.md`.

### Изменено

- Конфигурация интеграции теперь умеет включать входящие сообщения и валидировать доступность long poll ещё на этапе настройки.
- Runtime интеграции теперь хранит ресурсы записи отдельно, чтобы корректно перезапускать receiver и сервисы при reload/unload.

### Исправлено

- Улучшена обработка медиа и wall token: ошибки стали понятнее, а сценарии без пользовательского wall token деградируют безопаснее.
- Доработан options flow: обновление имени, группы и дополнительных параметров сохраняется стабильнее.

## 0.2.2 - 2026-04-15

### Исправлено

- Отправка видео без `VK wall access token` теперь сразу использует загрузку как документ вместо неудачной попытки сохранить VK-видео токеном сообщества.
- Для невалидного `VK wall access token` возвращается понятная ошибка `VK wall access token is invalid`.
- Публикация `ha_vk.send_post` без `VK wall access token` теперь не падает: текстовый пост отправляется, а вложение изображения пропускается.
- Обновлена документация по scope `video` и по получению пользовательского wall token через `vkhost`.

## 0.2.1 - 2026-04-15

### Добавлено

- В `README.md` и `README.en.md` добавлены наглядные примеры отправки фото и видео в сообщения группы, а также публикации постов на стене сообщества.

### Исправлено

- Исправлен flow редактирования настроек интеграции: обработчик options flow теперь создаётся корректно и лучше соответствует текущему API Home Assistant.

## 0.2.0 - 2026-03-17

### Добавлено

- Новый сервис `ha_vk.send_message` для отправки текста, изображения или видео одним вызовом.
- Поддержка параметра `type` для отправки видео как обычного VK-видео или как документа.
- Новый сервис `ha_vk.send_post` для публикации постов на стене сообщества, включая посты с изображением.
- Поддержка `entry_id` в сервисах `ha_vk.*`, если в Home Assistant настроено несколько записей интеграции.

### Исправлено

- Добавлена валидация payload: нельзя отправлять пустой запрос и нельзя передавать `image` и `video` одновременно.
- Улучшены ошибки конфигурации и сетевые сообщения при скачивании и загрузке медиафайлов.
- Добавлен fallback на загрузку видео как документа, если `video.save` недоступен для токена сообщества.
